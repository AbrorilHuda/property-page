# Halaman `/report` — Form Lapor Keluhan Klien Perumahan

Membuat halaman `/report` berisi form keluhan klien (ID Kavling, Proyek, Nama, No. HP, Keluhan) dengan data dummy, siap di-wire ke REST API nanti, dengan tampilan mengikuti design system situs (Tailwind v4, palet emerald/slate, font Outfit + Plus Jakarta Sans).

## File baru

### 1. `src/pages/report.astro` — halaman utama
- Komposisi mengikuti `index.astro`: `<Layout title="Lapor Keluhan | Bumi Group" description="...">` → `<Navbar />` → `<main>` → `<Footer />` → `<StickyWhatsApp />`.
- **Header section** gelap (`bg-slate-950`, ringkas seperti hero homepage, `pt-32` untuk kompensasi navbar fixed): eyebrow pill "Layanan Pelanggan", H1 "Lapor Keluhan", satu paragraf deskripsi.
- **Section form** (`bg-slate-50 py-20 md:py-28`): grid `lg:grid-cols-5` —
  - Kiri (`col-span-2`): kartu "Cara Melapor" berisi 3 langkah bernomor (isi form → verifikasi tim → tindak lanjut perbaikan) + kartu info kontak (telepon, WhatsApp, email, jam operasional dari `src/utils/config.ts`) dengan tombol WhatsApp sekunder.
  - Kanan (`col-span-3`): komponen `<ReportForm />`.
- Animasi scroll-reveal pakai class `reveal` / `reveal-delay-N` (sudah otomatis ditangani IntersectionObserver di `Layout.astro`).

### 2. `src/components/ReportForm.astro` — komponen form
- **Field sesuai permintaan**: ID Kavling (text, placeholder "cth. K-12"), Proyek (select), Nama Lengkap (text), No. HP/WhatsApp (tel), Keluhan (textarea).
- **Dummy data proyek**: array inline di frontmatter — Cluster Emerald, Cluster Sapphire, Cluster Diamond (mengikuti nama tipe rumah yang sudah ada di situs), dengan komentar TODO bahwa nanti diganti fetch dari API.
- **Styling identik `ContactForm.astro`**: input `w-full px-4 py-3.5 border-2 border-slate-300 rounded-xl focus:border-emerald-700 ...`, label `text-sm font-bold`, error per-field `text-red-600 text-sm font-bold hidden` + `role="alert"`, card wrapper `bg-white rounded-3xl p-6 sm:p-10 shadow-card border border-slate-200`. Select pakai `appearance-none` + chevron SVG agar konsisten dengan input lain.
- **Validasi vanilla JS** (pola ContactForm): semua field required, nama via `validateName`, no HP via `validateWhatsApp` dari `src/utils/validation.ts`, keluhan min. 10 karakter; error tampil saat blur dan saat submit.
- **Submit (simulasi REST API)**: delay 800ms → banner sukses dengan nomor tiket dummy (mis. `RPT-20260913-4821`) + form di-reset. Sertakan komentar berisi contoh `fetch` POST yang siap diaktifkan saat API asli tersedia. Banner error merah bila gagal. Tombol disabled + teks "Mengirim..." saat proses.
